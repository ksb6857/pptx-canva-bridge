## 굵기 문제를 잡기까지

처음에는 글자 크기 비율 문제로 봤다. 틀렸다. 캔바에서 같은 텍스트 상자를 열어
글꼴 패널을 직접 보고 원인을 찾았다.

캔바의 네모고딕은 웨이트가 넷이다.

```
가벼운 / 보통 / 중간 / 가장 굵은
```

업로드한 파일은 **중간**에 잡혀 있었다. pptx 안에는 `네모고딕 Heavy` 라고 적혀 있는데도
그랬다. 같은 슬라이드를 다른 선생님 파일과 나란히 놓고 보면 한 단계 차이가 눈에 띈다.

`b="true"` 를 뺀 사본을 만들어 다시 올렸더니 **가장 굵은**으로 잡혔다.

그 사본을 파워포인트에서 열어 보니 이번에는 볼드가 안 걸린 것처럼 보였다.
그래서 두 벌로 나눴다.

## 어떤 글꼴이 걸렸나

10월 교안에서 쓰인 글꼴과 겹친 곳이다.

```
네모고딕 Medium                158곳
네모고딕                        101곳   (이름에 웨이트 없음, 대상 아님)
네모고딕 Heavy                   14곳
Glacial Indifference Bold     10곳
윤굴림 Bold                       9곳
Arimo Bold                     4곳
Tlab 모던라운드 Bold                3곳
```

`네모고딕` 101곳은 이름에 웨이트가 없다. 이런 글꼴은 `b` 가 유일한 굵기 정보라
빼면 안 된다.

처음에는 이 목록을 코드에 그대로 박아 뒀다. 지금은 이름을 낱말 단위로 훑어 찾는다.
2026-09-08 에 두 방식의 결과를 비교했다. 10월 교안에서 둘 다 198곳으로 같았고,
만들어진 캔바용 파일은 멤버 204개가 전부 바이트 단위로 같았다.

## 임베드 글꼴

7개가 들어 있고 압축 전 기준 10.0MB 다.

```
네모고딕 / 네모고딕 Medium / 네모고딕 Heavy
Glacial Indifference Bold / Arimo Bold / Tlab 모던라운드 Bold / 윤굴림 Bold
```

일곱 개 모두 PC 에 설치돼 있지 않다. 그런데도 파워포인트는 제대로 그리고 편집도 된다.
선생님이 파일을 열어 글자를 고쳤을 때 `네모고딕 36.99pt` 가 그대로 유지된 것으로 확인했다.

**설치가 안 됐다고 파일이 잘못된 것이 아니다.** 이걸 몰라서 한동안 "캔바 내보내기가
틀어졌다"고 잘못 짚었다. pptx 와 같은 폴더의 PDF 를 열어 슬라이드마다 글자 크기를
맞춰 본 결과 5월 58장, 6월 44장 모두 어긋난 곳이 0 이었다.

임베드 글꼴을 빼면 16.7MB 가 11.9MB 가 된다.

## CRC 손상

3권 파일 두 개에서 나왔다.

```
(3팀_12회)001.pptx  ppt/media/image6.png   CRC 0x5FDB2332  55,090바이트  167×192px
(3팀_12회)003.pptx  ppt/media/image22.png  CRC 0x5FDB2332  55,090바이트  167×192px
```

파워포인트는 두 파일을 아무 문제 없이 열었다. 캔바만 업로드를 거부했다.
성한 사본에서 그 멤버만 가져와 갈아 끼웠다. 다른 바이트는 모두 그대로다.
슬라이드 28장과 6장, 발표자 노트가 전부 보존됐다.

`fix_crc.py` 는 2026-09-08 에 시험했다. 37장짜리 교안의 `ppt/media/image1.jpeg`
(531,305바이트) 한가운데 바이트를 뒤집어 깨뜨린 뒤 복구했다. 결과 파일은 멤버 211개가
원본과 전부 같았고 python-pptx 로 열려 슬라이드 37장, 노트 37장이 그대로였다.

## 아직 확인 못 한 것

- 캔바의 다른 한글 글꼴도 웨이트가 넷인지, 아니면 글꼴마다 다른지 확인하지 않았다.
- `b` 를 뺀 사본을 캔바에서 편집한 뒤 다시 pptx 로 내려받으면 어떻게 되는지 확인하지
  않았다. 캔바가 글꼴을 다시 구우므로 녹화용으로는 쓰지 않는다.
- 이름에 `Light` 가 든 글꼴에 `b` 가 겹쳤을 때 캔바가 어떻게 잡는지 확인하지 않았다.
  그래서 스크립트는 중간 이상 웨이트에서만 `b` 를 뺀다.
